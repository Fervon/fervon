The detectors

What it catches

The concrete tricks agents use to turn CI green without doing the work.

Circular mocks

Mocking the exact function under test, so the assertion only checks the mock.

Deleted & skipped tests

Tests removed, commented out or marked .skip/xfail in the same PR that touches their code.

Assertions deleted, test kept

The expect is gone and the it(...) stays: the same number of green tests, checking nothing.

Tautological asserts

expect(true).toBe(true), assert.strictEqual(true, true), assert 1 == 1, empty test bodies — green that proves nothing.

Relaxed thresholds

Coverage minimums lowered, or the CI step disarmed with continue-on-error / || true, to dodge a red build.

Mass-regenerated snapshots

A wave of snapshot updates that quietly bless whatever the new output happens to be.

Swallowed failures

npm test || true, --passWithNoTests, an empty catch {} around the assertions: it failed, and nobody finds out.

Weakened assertions

A strict matcher swapped for one that can barely fail: toBe becomes toBeTruthy, an exact value becomes any(Number).

Commented-out assertions

The assertion is not fixed and not deleted — just commented out, so the test still runs and checks one thing less.

Those cards are the families. Under them ship 11 deterministic rules, each with the snippet that trips it and a one-line way to silence it when the change was deliberate — full rule catalog. FAQ

Frequently asked questions

Do I need an API key or an LLM?

No. Veredicto runs on your CI runner, is deterministic, and uses no LLM and no API key. Not even the licence goes online: it is an Ed25519 signature verified locally, so Veredicto works on a runner with no egress at all. Nothing about your diff ever leaves your machine.

Will it block my pull requests?

By default it runs in warn mode: it comments what it finds without blocking. Block mode is opt-in. Every rule has an explanation and can be suppressed with a PR comment.

How is it different from CodeRabbit or GitHub's native review?

CodeRabbit reviews quality with a paid LLM; GitHub validates security. Neither checks test integrity. Veredicto does one thing: detect when the tests were gamed — deterministic, instant, and without sending your diff anywhere.

What exactly is test-gaming?

Making CI go green without the code being correct: deleting or .skip-ing tests, tautological asserts, mocks of the thing under test, mass-regenerated snapshots, or relaxed coverage thresholds.

Does it work on GitLab or Bitbucket?

GitHub Actions first. GitLab and Bitbucket are on the roadmap. Join the list to know when they land.
