Project releases

What has shipped from the catalogue, with the version and what actually changes.

  1. August 19, 2026 Lookspan v0.5.3

    Hardened security and external Postgres

    Lookspan can now sit on an external Postgres alongside local storage, and ships a security hardening pass on the ingest server. It stays local-first: the dashboard lives at 127.0.0.1:3100 via npx lookspan and no span leaves your machine unless you ask it to.

  2. August 12, 2026 Veredicto v0.4.0

    Veredicto goes paid, with the licence verified without leaving the runner

    One product, $19 per repository, self-serve and with no tiers. The interesting part is how the licence is checked: an Ed25519 signature validated locally against a public key embedded in the source. No licence server, no phone-home and no telemetry — on a runner with no egress it still works. A tool that reads your diffs has no business reporting on them, and that applies to its own billing too. The gate is fail-closed and runs before the diff is read: an unlicensed run fails and says why, and never resembles "Veredicto ran and your PR is clean". Everything up to 0.3.3 stays MIT, irrevocably.

  3. August 12, 2026 launchpad v1.3.0

    Open a project in your editor from the panel — and a security hole closed

    The detail drawer now opens any project in your editor, your file manager or a terminal: the cd the README promised to save you. The endpoint existed but no button ever called it, and it only knew about VS Code; the editor now comes from settings.editorCommand, so subl, webstorm or nvim work just as well. Something more serious got closed along the way: the old route used execFile(cmd, [path], { shell: true }), which concatenates arguments into a shell string without escaping them — a project folder name could run commands.

  4. August 12, 2026 ClaudeScope v0.5

    Jump to the message, a weekly digest and an HTML report that opens offline

    Opening a session from a search result now scrolls to the matched message and highlights it, which was the missing half of find→read. There is also --weekly, a plain-text "Scope Report" —this week versus last, streak, archetype, top project, percentile— meant for a scheduled task, and export to a self-contained .html that opens offline. Plus local team mode: --dump-sessions writes a session dump and --merge aggregates several dumps into shared analytics. Zero infrastructure and nothing gets uploaded.

FAQ

Frequently asked questions

What is this blog about?

Two things: each Fervon project's releases as they ship, and long-form articles on how software gets built by directing fleets of AI agents. No filler: only what was measured while working gets published.

How often does it publish?

When there is something measured worth saying. It is a one-person studio, so one useful article a month beats four filler posts a week.

Do you have to subscribe to read it?

No. No paywall, no signup and no popup asking for your email. All the content is open, like most of the code.

Who writes the articles?

Jonathan Martín, founder and sole person behind Fervon. The articles describe his actual working method, limits and things that went wrong included.

What comes out of here

The articles describe the method; the catalogue is the evidence. Two paid products and six open-source tools, all built this way.
